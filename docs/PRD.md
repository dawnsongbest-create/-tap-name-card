### 0.4 重要覆盖决策

以下为对早期讨论中可能产生歧义的最终覆盖决定：

- **收藏与认识请求完全独立。**收藏是静默、单向的保存动作，不通知名牌主人，也不自动发起认识请求。
- **认识请求不会自动收藏对方名牌。**发送者可在“已发出的请求”中继续查看请求所对应的名牌，但这不等于收藏。
- **名牌主人只能通过“接受并回赠名牌”接受认识请求。**不存在“先接受、后回赠”或“先聊天”的中间状态。
- **双方完成名牌回赠后才创建相遇关系。**浏览、收藏、发送请求均不创建相遇。
- **完成相遇后才允许申请交换联系方式。**联系方式仍需接收方明确同意，且双方各自选择愿意提供的联系方式。
- **第一版不建设站内聊天。**共同兴趣仅用于帮助现实交流和提供开场建议。
- **第一版不依赖 NFC 硬件上线。**NFC 为未来载体，MVP 先通过微信分享、小程序码和视觉图片完成验证。

# 1. 产品概述

## 1.1 一句话定义

「碰一下名牌」是一款面向手机的可视化自我介绍与线下破冰微信小程序。用户可以创建多张代表自己不同侧面的名牌，在真实社交场景中选择其中一张，通过微信分享、小程序码以及未来的 NFC 贴片主动递给别人。

## 1.2 产品愿景

让每一个不擅长开口介绍自己的人，都可以通过一张漂亮、真实、有个性的名牌，被别人更好地认识。

## 1.3 核心价值

很多内向、慢热或不擅长即时表达的人并不是没有内容。他们可能拥有充实的生活、长期投入的兴趣、独特的经历和非常具体的喜好，但在第一次见面时，很难快速组织语言介绍自己。

本产品不是替代现实交流，而是把最难的第一步变得更轻：

> 用户提前整理好自己想表达的一面，在合适的时刻把名牌递出去。对方可以舒服地浏览，找到共同点，再决定是否发起认识请求。

## 1.4 产品希望创造的五种感受

按重要性排列：

1. **我被很好地介绍出来了。**
2. **这个东西很好玩，我也想给自己做一张。**
3. **我终于不用尴尬地介绍自己了。**
4. **原来我们有这么多共同点。**
5. **我今天的状态被保存下来了。**

## 1.5 产品形态

第一阶段：

- 微信小程序；
- 微信小程序卡片分享；
- 小程序码；
- 适合社交媒体发布的纯视觉名牌图片。

未来扩展：

- NFC 社交贴片；
- NFC 电子吧唧；
- NFC 工卡；
- NFC 工卡壳；
- NFC 手机壳贴片；
- NFC 挂件、手环等个人物件。

所有未来实体载体接入同一套账号、名牌和绑定体系。

# 2. 产品背景与问题定义

## 2.1 用户问题

在兴趣活动、朋友聚会、社群线下活动和朋友带朋友等场景中，参与者经常需要进行自我介绍。传统方式通常要求用户在很短时间内说出姓名、职业、兴趣和来这里的目的，这会带来以下问题：

- 不擅长表达的人容易紧张；
- 自我介绍容易停留在姓名、公司、职位等浅层信息；
- 充实的生活和兴趣无法在几十秒内表达；
- 参与者很难快速发现共同话题；
- 直接交换微信又可能显得过快或带来隐私压力；
- 活动结束后，容易忘记对方当时介绍过什么。

## 2.2 市场问题

现有电子名片产品大多面向企业销售、客户管理和商业获客，常见问题包括：

- 页面视觉偏企业模板，缺少年轻用户愿意主动分享的设计感；
- 内容围绕公司、职位、电话、产品和销售线索；
- 交互强调访客追踪、销售转化和 CRM；
- 对日常社交、兴趣人格和轻松破冰支持不足；
- NFC 常被当作二维码替代，没有与数字身份和真实相遇形成完整体验。

本产品不以商业化为首要目标，而是以“做好玩的社交玩具”为导向，聚焦个人表达、现实破冰和相遇收藏。

# 3. 产品定位与边界

## 3.1 产品是什么

- 一款可视化自我介绍工具；
- 一款辅助现实社交破冰的轻社交产品；
- 一套可绑定到不同实体物件上的数字身份系统；
- 一张持续更新、可重复递出的个人名牌；
- 一个帮助用户发现共同兴趣的现实交流辅助工具。

## 3.2 产品不是什么

- 不是企业电子名片；
- 不是销售 CRM；
- 不是客户线索收集工具；
- 不是陌生人匹配平台；
- 不是恋爱交友平台；
- 不是“附近的人”；
- 不是公开社交关系链；
- 不是内容信息流社区；
- 不是站内即时聊天产品；
- 不是以粉丝、人气、曝光或排行榜为中心的平台。

## 3.3 核心产品原则

### 3.3.1 先表达，再互动

用户打开名牌后的第一感受应是“这个人被很好地呈现出来了”，而不是被要求登录、关注或添加好友。

### 3.3.2 浏览没有压力

匿名用户可以完整浏览公开名牌。浏览行为不会通知名牌主人，不展示已读状态，也不会生成公开访客记录。

### 3.3.3 现实社交优先

产品帮助已经出现在同一现实场景中的人互相了解，不主动向用户推荐陌生人。

### 3.3.4 用户控制展示

用户决定：

- 创建哪些名牌；
- 当前递出哪一张；
- 展示哪些内容；
- 是否允许收藏、认识请求和联系方式申请；
- 是否接受并回赠；
- 提供哪些联系方式；
- 是否保存、分享或删除相遇记录。

### 3.3.5 不制造社交竞争

不向普通用户展示：

- 粉丝数；
- 公开好友数；
- 公开收藏数；
- 名牌浏览量；
- 收到请求数量排名；
- 人气值；
- 热门榜单。

### 3.3.6 设计本身就是功能

名牌需要漂亮到用户愿意：

- 当面递出；
- 保存到相册；
- 发布到朋友圈、小红书、微博或 Instagram；
- 在群聊和社群中作为自我介绍；
- 邀请朋友也创建一张。

# 4. 目标用户与核心场景

## 4.1 目标用户

产品不限定特定年龄、职业或身份，面向存在以下需求的人：

- 不擅长主动介绍自己；
- 初次见面时容易紧张或不知道说什么；
- 有丰富兴趣和生活，但难以快速表达；
- 希望以更有设计感的方式展示个人身份；
- 希望区分社交、朋友、工作等不同侧面；
- 希望在社交媒体上拥有一张统一的自我介绍卡片。

## 4.2 首个重点场景

**兴趣活动中认识新朋友。**

活动包括但不限于：

- 展览和看展活动；
- 音乐节、演出和乐迷聚会；
- 摄影、读书、桌游和手作活动；
- 漫展、谷圈和动漫兴趣活动；
- 社群线下活动；
- 课程、工作坊和共同学习活动。

## 4.3 其他核心场景

### 4.3.1 朋友聚会与日常破冰

在多人聚餐、朋友组局、派对和朋友带朋友的场景中，用户主动递出名牌，减少轮流口头介绍的压力。

### 4.3.2 社交媒体展示

用户将名牌生成视觉图片，用于朋友圈、小红书、微博、Instagram、群聊自我介绍、社群新成员介绍和个人主页置顶内容。

### 4.3.3 行业交流和简历展示

用户使用独立的简历名牌介绍职业经历、核心能力、代表项目和合作诉求。简历名牌与社交名牌使用不同的信息结构和模板。

### 4.3.4 未来 NFC 触发

用户将当前名牌绑定到 NFC 贴片、电子吧唧、工卡或卡套，允许他人通过碰触打开当前名牌或指定名牌。

# 5. 核心术语

| 术语 | 定义 |
|---|---|
| 名牌 | 用户创建的可视化自我介绍页面 |
| 社交名牌 | 以兴趣、人格、生活状态和可聊话题为核心的名牌 |
| 简历名牌 | 以职业身份、能力、经历、项目和合作目的为核心的名牌 |
| 当前名牌 | 用户当前选择用于通用分享入口的唯一名牌 |
| 名牌主人 | 创建并发布该名牌的用户 |
| 浏览者 | 通过分享、小程序码或未来 NFC 打开名牌的人 |
| 收藏 | 用户单方面、静默地保存一张名牌，不通知名牌主人 |
| 认识请求 | 浏览者明确向名牌主人递出自己的一张名牌，并请求对方回应 |
| 接受并回赠 | 名牌主人接受认识请求的唯一方式，同时选择一张自己的名牌回赠 |
| 相遇 | 双方完成名牌回赠后形成的双向私密关系记录 |
| 相遇事件 | 同一对用户在不同时间、不同场景下再次见面的记录 |
| 相遇册 | 用户私密保存相遇关系和相遇事件的页面 |
| 联系方式申请 | 完成相遇后，一方向另一方申请互换各自选定的联系方式 |
| 名牌快照 | 在收藏、请求或相遇发生时保存的不可变名牌版本 |
| 视觉名牌图片 | 为社交媒体专门生成的独立图片，不是页面截图 |
| NFC 设备 | 未来承载名牌入口的 NFC 贴片、吧唧、工卡或其他物件 |

# 6. MVP 范围与优先级

## 6.1 当前阶段定义

当前阶段为小规模可用 MVP。预期早期注册用户为数百至数千，同时在线用户较少。

MVP 目标是：

- 可以在真实 iPhone 和 Android 手机上运行；
- 可以完成微信小程序审核和小范围发布；
- 可以邀请真实用户完成创建、分享、认识、回赠和联系方式交换；
- 不为尚未出现的大规模用户提前建设复杂架构。

## 6.2 P0：核心可用 MVP，必须实现

### 账号与安全

- 微信小程序身份识别和账号建立；
- 用户协议和隐私政策确认；
- 账号状态；
- 账号注销；
- 拉黑和举报；
- 基础内容审核；
- 所有关键写操作通过云函数进行权限校验。

### 名牌创建

- 社交名牌和简历名牌两种独立类型；
- 先选模板，再进入编辑；
- 表单填写并实时预览；
- 内容模块自由组合；
- 草稿自动保存与恢复；
- 完整预览；
- 发布、隐藏、删除和复制；
- 多张名牌管理；
- 设置当前名牌；
- 修改已发布名牌时保留旧公开版本，直到新版本审核通过。

### MVP 模板

社交名牌：

1. Apple Minimal；
2. 杂志人物页；
3. 手账拼贴；
4. 动漫角色卡。

简历名牌：

1. 极简职业卡；
2. 项目作品卡。

### 浏览和分享

- 未登录用户匿名浏览完整公开名牌；
- 微信小程序卡片分享；
- 生成小程序码；
- 生成 3:4、9:16、1:1 视觉名牌图片；
- 可选择图片中是否包含小程序码；
- 收藏名牌；
- 分享按钮和举报入口。

### 社交闭环

- 发起认识请求；
- 发起前明确选择和确认自己递出的名牌；
- 名牌主人收到小程序内通知；
- 名牌主人只能“接受并回赠”、暂时忽略或不接受；
- 接受并回赠后创建相遇；
- 相遇册和名牌快照；
- 标准标签共同兴趣匹配；
- 相遇私人备注；
- 联系方式申请、接受、拒绝、撤回和撤销；
- 30 天认识请求有效期；
- 联系方式申请被拒后默认 7 天冷却期，服务端可配置。

### 通知

- 收到认识请求；
- 对方接受并回赠；
- 收到联系方式申请；
- 联系方式申请通过或未通过；
- 名牌审核结果。

## 6.3 P1：增强 MVP 体验，P0 稳定后实现

- AI 表达助手；
- 更丰富的共同兴趣映射；
- 相遇事件时间线；
- 单次相遇视觉图片分享；
- 微信订阅消息；
- 更完整的无障碍适配；
- 模板轻动画细节；
- 运营所需的轻量审核工具；
- 视觉图片更多主题变体。

## 6.4 P2：未来规划，不阻塞 MVP

- NFC 社交贴片实际绑定；
- NFC 当前名牌模式和固定名牌模式；
- 电子吧唧、电子工卡、工卡壳等实体产品；
- Y2K 数字档案、轻复古档案等更多模板；
- L3 自由创作编辑器；
- 活动专属模板；
- H5 公开名牌；
- 简历 PDF 链接；
- 多端产品；
- 用户共创模板体系。

## 6.5 第一版明确不做

- 陌生人推荐；
- 附近的人；
- 滑动匹配；
- 恋爱匹配；
- 站内即时聊天；
- 私信；
- 动态广场；
- 推荐信息流；
- 点赞和公开评论；
- 公开关注和粉丝；
- 排行榜和人气值；
- 访客身份追踪；
- 企业员工管理；
- 销售 CRM；
- 广告；
- 付费会员；
- 模板商城；
- 自动添加微信好友；
- 自动读取微信好友或手机通讯录；
- 实时位置和精确地图定位；
- 用户自定义字体上传；
- 视频背景和背景音乐；
- 完整自由画布编辑器；
- 大规模推荐算法和数据仓库。

# 7. 信息架构

## 7.1 底部导航

### 首页

用于管理和递出当前名牌：

- 当前名牌大卡预览；
- 切换当前名牌；
- 递出名牌；
- 展示小程序码；
- 生成视觉图片；
- 编辑当前名牌；
- 创建新名牌；
- 待处理认识请求；
- 最近相遇入口。

### 相遇

用于管理双方完成回赠后的私密记录：

- 相遇列表；
- 相遇详情；
- 共同兴趣；
- 私人备注；
- 相遇事件；
- 联系方式状态；
- 分享单次相遇；
- 隐藏、删除、拉黑或举报。

### 我的

用于管理账号与个人内容：

- 我的名牌；

# 8. 用户身份、登录与访问规则

## 8.1 匿名浏览者

可以：

- 浏览公开名牌；
- 查看名牌主人主动公开的信息；
- 分享名牌；
- 举报名牌；
- 关闭页面。

不可以：

- 收藏；
- 发起认识请求；
- 接受并回赠；
- 创建相遇；
- 申请联系方式；
- 查看私密联系方式；
- 查看相遇册。

匿名用户点击互动按钮时才显示登录引导。不得在进入公开名牌页面时强制登录。

## 8.2 已登录但没有已发布名牌的用户

可以：

- 浏览和收藏；
- 创建名牌。

点击“认识一下”时提示：

> 先准备一张自己的名牌，才能把自己介绍给对方。

操作：

- 创建名牌；
- 继续编辑草稿；
- 暂时只收藏；
- 取消。

## 8.3 已登录且拥有已发布名牌的用户

可以使用完整互动能力，但仍受名牌隐私开关、拉黑关系、账号状态和频率限制约束。

## 8.4 被限制用户

- 可以访问和导出自己的必要数据；
- 不得发布新名牌；
- 不得发起认识请求；
- 不得申请交换联系方式；
- 公开名牌根据风险等级隐藏；
- 限制原因和申诉路径由后续运营流程确定。

## 8.5 权限原则

前端隐藏按钮不是权限控制。所有云函数必须校验：

- 当前用户身份；
- 资源所有权；
- 业务状态；
- 拉黑关系；
- 是否重复提交；
- 输入是否合法；
- 是否超过频率限制。

# 9. 名牌类型

## 9.1 社交名牌

回答：

- 我是一个怎样的人；
- 我最近喜欢什么；
- 我们可能聊什么；
- 我正在做什么；
- 我想认识什么样的人。

规则：

- 允许昵称和半匿名身份；
- 不要求真实姓名；
- 不要求真人头像；
- 可以使用虚拟形象、宠物、风景、符号、Emoji 或纯文字；
- 联系方式默认不公开。

## 9.2 简历名牌

回答：

- 我是谁；
- 我现在做什么；
- 我擅长什么；
- 我做过什么；
- 我在寻找什么机会。

规则：

- 使用与社交名牌独立的信息结构和模板；
- 可以使用职业昵称；
- 个人网站、公开作品集等可由用户设置为公开；
- 微信、电话、私人邮箱等仍默认需要申请后可见。

## 9.3 多名牌规则

- 用户最多创建 10 张名牌，服务端可配置；
- 用户可以拥有多张社交和简历名牌；
- 任意时刻仅有一张“当前名牌”；
- 通用分享入口打开当前名牌；
- 固定名牌分享链接始终打开对应名牌；
- 未来 NFC 当前名牌模式跟随当前名牌，固定名牌模式保持指定名牌；
- 回赠名牌时可选择任意已发布名牌，不改变当前名牌。

# 10. 模板系统与视觉设计

## 10.1 模板选择原则

用户创建名牌时必须先选择名牌类型和模板，再进入编辑器。模板选择前不要求回答问题或填写资料。

模板列表使用虚构示例内容展示：

- 模板名称；
- 预览图；
- 一句话风格说明；
- 编辑自由度；
- 是否支持多图；
- 是否支持深浅模式；
- 是否包含轻动画。

## 10.2 视觉原则

- 手机竖屏优先；
- 第一屏接近完整手机视口；
- 高度视觉化，但信息不过载；
- 适合直接导出为社交媒体图片；
- 静态设计为主，只加入不影响阅读的轻微动画；
- 动画不是理解内容的必要条件；
- 用户系统开启“减少动态效果”时，应关闭或弱化动画。

## 10.3 编辑等级

### L1：固定结构模板

允许：

- 修改文字和图片；
- 主题色；
- 深浅模式；
- 模块显示和隐藏；
- 少量背景选项。

不允许：

- 改字体；
- 任意移动元素；
- 改核心版式。

### L2：模块化模板

在 L1 基础上允许：

- 调整模块顺序；
- 选择图片布局；
- 选择标签样式；
- 选择预设装饰元素；
- 调整部分文字对齐。

### L3：自由创作模板

支持拖动、缩放和叠放元素。P2 规划，MVP 不实现。

## 10.4 MVP 社交模板

### T-SOCIAL-01 Apple Minimal

- 编辑等级：L1；
- 大量留白；
- 黑、白、银灰和柔和渐变；
- 大字号昵称；
- 三个核心标签；
- 轻微玻璃质感或呼吸光效；
- 支持头像、符号、Emoji、纯文字和抽象视觉；
- 为默认模板和品牌主视觉。

### T-SOCIAL-02 杂志人物页

- 编辑等级：L2；
- 大图优先；
- 杂志封面式标题；
- 一句人物自述；
- 支持一至四张图片；
- 重点优化视觉图片导出。

### T-SOCIAL-03 手账拼贴

- 编辑等级：L2；
- 照片、贴纸、胶带和便签元素；
- 支持一至四张生活图片；
- 只支持预设布局与装饰，不做自由画布。

### T-SOCIAL-04 动漫角色卡

- 编辑等级：L2；
- 角色主视觉；
- 兴趣徽章；
- 近期关注作品；
- 欢迎聊的话题；
- 轻量属性面板；
- 不得内置未经授权的版权角色素材。

## 10.5 MVP 简历模板

### T-RESUME-01 极简职业卡

- 当前身份；
- 一句话能力描述；
- 三项核心能力；
- 当前目的；
- 简洁、克制、适合行业交流。

### T-RESUME-02 项目作品卡

- 代表项目优先；
- 项目图片；
- 用户角色和贡献；
- 项目结果；
- 作品链接。

## 10.6 模板切换

用户更换模板时：

1. 已填写内容不得丢失；
2. 新模板不支持的模块进入“暂未展示”状态；
3. 系统明确提示受影响模块；
4. 用户可以切回原模板恢复展示；
5. 不得删除不兼容内容。

提示文案：

> 新模板暂时无法展示其中 2 个模块，但内容会继续保留。

## 10.7 模板版本管理

每张名牌记录：

- `templateId`；
- `templateVersion`；
- `editorLevel`；
- `themeConfig`；
- `moduleConfig`。

模板不兼容升级时，旧名牌继续使用旧版渲染，除非用户主动升级。

- 用户停止输入 2 秒；
- 切换模块；

- 页面进入后台；
- 用户离开编辑页。

保存状态：

- 正在保存；
- 已保存；
- 保存失败，正在重试；
- 已保存在本机，联网后同步。

要求：

- 远端保存失败时保留本地临时草稿；
- 网络恢复后重试；
- 冲突时以用户当前设备最近明确编辑版本为主，但必须保留服务器旧版本用于恢复；

1. 选择图片；
2. 本地立即预览；
3. 客户端压缩；
4. 上传云存储；
5. 成功后替换为云文件标识；
6. 保存草稿；
7. 失败时保留本地选择并提供重试。

建议限制：

- 单张原图不超过 10 MB；
- 仅支持常见安全图片格式；
- 社交名牌生活图片最多 4 张；
- 上传后生成或使用不同尺寸版本；
- 导出图片使用高清版本，页面浏览使用压缩版本。

# 14. AI 表达助手（P1）

## 14.1 定位

AI 是可选的表达整理助手，不是强制 onboarding，不替用户虚构经历，也不进行人格诊断。

## 14.2 入口

可在以下字段旁显示“帮我表达”：

- 一句话介绍；
- 当前状态；
- 兴趣标签；
- 性格关键词；
- 想认识什么样的人；
- 想聊的话题；
- 简历能力描述；
- 项目简介；
- 个人简介。

## 14.3 交互

用户先进入编辑器，再主动调用 AI。

推荐入口：

- 帮我把这句话说顺；
- 我不知道怎么介绍；
- 从这些碎片里整理一下；
- 给我几个不同版本；
- 写得更像我一点。

AI 每次最多提出一个问题，最多主动提问 3 轮。用户可以跳过或结束。

推荐问题示例：

- 把最近让你开心的三件小事丢给我，我帮你整理；
- 你遇到什么话题会突然变得很能聊？
- 写几个零散关键词就行，不需要完整句子。

## 14.4 模式

### 整理碎片

输入关键词或不完整句子，输出：

- 3 个一句话介绍；
- 推荐兴趣标签；
- 可选性格关键词。

### 改写已有内容

选项：

- 更自然；
- 更有趣；
- 更简洁；
- 更真诚；
- 更有个性；
- 更适合简历。

### 一起聊聊

通过最多 3 轮问题帮助用户提炼表达。

## 14.5 输出规则

云函数必须返回结构化结果：

```json
{
  "requestId": "string",
  "fieldType": "social_intro",
  "candidates": [
    {"text": "工作日认真生活，周末认真乱逛。", "tone": "轻松", "length": 16},
    {"text": "慢热，但遇到喜欢的话题会突然说很多。", "tone": "自然", "length": 19}
  ],
  "suggestedTags": ["城市散步", "独立音乐"],
  "safetyStatus": "pass"
}
```

要求：

- 最多 3 个候选；
- 只有用户点击“使用这句”才写入；
- 不自动覆盖原文；
- 不自动发布；
- 不编造学历、工作、项目、兴趣或敏感身份；
- 不根据内容推断心理疾病或人格障碍；
- 不将用户内容用作公开示例。

## 14.6 最小上下文

发送给模型的内容仅包括：

- 名牌类型；
- 当前字段；
- 用户主动输入；
- 与当前任务相关的已填字段；
- 目标语气；
- 字数限制。

不得默认发送完整联系方式、相遇记录和无关账号资料。

## 14.7 失败处理

- 保留用户输入；
- 提示“刚才没有整理成功”；
- 允许重试；
- 允许返回手动编辑；
- AI 失败不得阻塞名牌发布。

# 15. 名牌预览、发布与版本

## 15.1 完整预览

- 与公开页面复用同一渲染组件；
- 顶部提示“这是别人看到的样子”；
- 支持完整滚动；
- 可返回编辑；
- 满足条件后可提交发布。

## 15.2 发布前校验

- 必填字段完整；
- 图片上传完成；
- 字数、数量和链接合法；
- 模板和名牌类型匹配；
- 账号正常；
- 内容审核通过或进入审核状态。

失败必须定位具体字段或图片，不能只显示“发布失败”。

## 15.3 名牌状态

```text
DRAFT
  -> 提交发布 -> REVIEWING
REVIEWING
  -> 审核通过 -> PUBLISHED
  -> 审核失败 -> REJECTED
REJECTED
  -> 修改后重新提交 -> REVIEWING
PUBLISHED
  -> 用户隐藏 -> HIDDEN
  -> 编辑新版本 -> REVIEWING_NEW_VERSION（旧公开版本继续可见）
  -> 用户删除 -> DELETED
HIDDEN
  -> 重新发布 -> REVIEWING
  -> 删除 -> DELETED
```

数据库可用统一 `REVIEWING` 状态和 `pendingContent` 表示新版本审核，但产品行为必须符合上述规则。

## 15.4 发布内容与草稿分离

- `draftContent`：当前编辑内容；
- `publishedSnapshotId`：最近审核通过的不可变快照；
- 用户编辑已发布名牌时，不立即改变公开页面；
- 新版本通过审核后才替换公开快照。

## 15.5 设置当前名牌

发布成功后可选择：

- 设置为当前名牌；
- 保持原当前名牌；
- 直接分享。

切换当前名牌后：

- 首页更新；
- 通用分享入口更新；
- 未来 NFC 当前名牌模式更新；
- 历史收藏和相遇快照不更新。

# 17. 收藏

## 17.1 定义

收藏是用户单方面保存名牌的动作，适用于：

- 喜欢名牌设计；
- 暂时不想发起认识请求；
- 希望以后继续查看；
- 保存朋友公开分享的名牌。

## 17.2 行为

收藏不会：

- 通知名牌主人；
- 发起认识请求；
- 请求对方回赠；
- 创建相遇；
- 开放联系方式。

## 17.3 收藏内容

- 保存当时的名牌快照；
- 同一用户对同一名牌只保留一条有效收藏；
- 用户可以取消收藏；
- 名牌隐藏或删除后，收藏列表保留缩略快照并显示“这张名牌已经不可查看”；
- 不向名牌主人展示收藏者身份或收藏数。

## 17.4 状态

```text
NOT_COLLECTED -> COLLECTED -> REMOVED
```

# 18. 认识请求

## 18.1 含义

“认识一下”表示：

- 我看过你的名牌；
- 我愿意让你知道我是谁；
- 我将递出自己选择的一张名牌；
- 你可以决定是否接受并回赠。

它不表示：

- 已经成为好友；
- 已经互相关注；
- 已经获得联系方式；
- 对方必须回应。

## 18.2 发起条件

- 用户已登录；
- 账号正常；
- 至少有一张已发布名牌；
- 双方不存在拉黑关系；
- 对方名牌允许认识请求；
- 不是自己的名牌；
- 未超过频率限制；
- 同一对用户没有有效的重复待处理请求。

## 18.3 发起确认

点击“认识一下”后展示：

- 对方名牌摘要；
- 自己将递出的名牌；
- 可切换自己的其他已发布名牌；
- 操作说明。

文案：

> 你会把这张名牌递给对方。对方会收到通知，并决定是否接受并回赠自己的名牌。

按钮：

- 递出我的名牌；
- 再看看。

## 18.4 发送结果

成功提示：

> 名牌已经递出去了。对方回应后，你们会出现在彼此的相遇册中。

系统：

- 创建一条请求；
- 保存发送者和目标名牌快照；
- 生成接收方通知；
- 在发送者“已发出的请求”中展示状态；
- 不自动收藏目标名牌；
- 不创建相遇。

## 18.5 名牌主人处理方式

仅允许：

1. 接受并回赠名牌；
2. 暂时忽略；
3. 不接受；
4. 举报或拉黑。

不提供：

- 单独接受；
- 文字回复；
- 表情回复；
- 语音回复；
- 站内聊天；
- 已读状态。

## 18.6 接受并回赠

页面展示：

- 对方完整名牌；
- 对方一句话介绍；
- 双方可能的共同兴趣；
- 自己可回赠的已发布名牌。

默认选中当前名牌，可选择其他名牌。

确认文案：

> 回赠后，你们会出现在彼此的相遇册中，也可以申请交换联系方式。

按钮：

- 确认回赠；
- 再看看。

## 18.7 暂时忽略

- 请求保留在待处理列表；
- 发起方只看到“等待对方回应”；
- 不显示已读；
- 不发送催促；
- 30 天后自动过期。

## 18.8 不接受

发起方看到：

> 对方暂时没有接受这次认识请求。

不得使用：

- 被拒绝；
- 认识失败；
- 匹配失败；
- 对方不想认识你。

## 18.9 请求状态机

```text
PENDING
  -> 接受并回赠 -> RETURNED
  -> 不接受 -> DECLINED
  -> 发起方撤回 -> CANCELLED
  -> 30 天未处理 -> EXPIRED
  -> 一方拉黑 -> CANCELLED
```

只有 `RETURNED` 可以创建相遇。

## 18.10 原子性和幂等

“接受并回赠”必须作为服务端原子操作：

1. 校验请求仍为 PENDING；
2. 校验回赠名牌有效；
3. 创建回赠快照；
4. 更新请求状态；
5. 创建或更新相遇；
6. 保存双方快照；
7. 计算共同兴趣；
8. 创建双方通知。

重复点击不能：

- 重复创建相遇；
- 重复发送通知；
- 重复保存业务记录。

# 19. 相遇册

## 19.1 创建条件

仅当认识请求状态变为 `RETURNED` 时创建或更新相遇。

## 19.2 数据规则

- 同一对用户只有一个相遇关系；
- 使用排序后的双方用户 ID 生成唯一 `pairKey`；
- 可以包含多个相遇事件；
- 保存双方当时的名牌快照；
- 后续修改名牌不覆盖历史快照；
- 用户可以查看对方当前公开名牌，但历史相遇仍显示原快照。

## 19.3 相遇列表

展示：

- 对方名牌缩略图；
- 昵称；
- 共同兴趣；
- 首次或最近相遇时间；
- 联系方式状态；
- 私人备注摘要。

不展示：

- 对方人气；
- 对方收到多少名牌；
- 好友排名；
- 公开关系数量。

空状态：

> 这里会保存你和别人互相回赠过的名牌。下次不知道怎么介绍自己时，可以把名牌递出去。

## 19.4 相遇详情

- 双方名牌快照；
- 共同兴趣；
- 相遇事件时间线；
- 私人备注；
- 联系方式状态；
- 申请交换联系方式；
- 分享这次相遇（P1）；
- 对自己隐藏相遇；
- 拉黑或举报。

## 19.5 私人备注

- 每一方独立保存；
- 另一方永远不可见；
- 最多 500 字符；
- 不参与共同兴趣和 AI 分析。

## 19.6 相遇事件

事件字段：

- 时间；
- 场景；
- 来源；
- 用户私人备注。

场景选项：

- 兴趣活动；
- 朋友聚会；
- 工作活动；
- 学校或社团；
- 旅行；
- 日常偶遇；
- 线上认识；
- 自定义。

不自动采集精确位置。

## 19.7 相遇状态

```text
ACTIVE
  -> 用户对自己隐藏 -> HIDDEN_FOR_USER
  -> 一方拉黑 -> BLOCKED
```

MVP 不要求实现双方共同解除关系。用户删除相遇只影响自己视图，不删除另一方记录和安全审计数据。

# 20. 共同兴趣

## 20.1 数据来源

只使用双方主动填写并允许用于匹配的：

- 兴趣标签；
- 最近喜欢；
- 最近在看；
- 最近在听；
- 想尝试；
- 想聊的话题。

不得使用：

- 私人备注；
- 联系方式；
- 精确位置；
- AI 未经确认的推断；
- 草稿；
- 敏感经历。

## 20.2 MVP 匹配方法

- 优先使用标准标签 ID 精确匹配；
- 自定义标签保存展示文本和标准化文本；
- 可以维护相关标签映射，例如“摄影”和“胶片摄影”；
- 不在每次页面打开时调用大模型判断；
- 匹配结果可解释、可复现。

## 20.3 展示时机

- 发起认识请求前：登录且有名牌的浏览者可看到“你们可能都喜欢……”；
- 名牌主人处理请求时：展示具体共同点；
- 创建相遇后：完整展示共同兴趣和开场建议。

## 20.4 开场建议

示例：

> 你们都喜欢城市散步，可以问问对方最近最喜欢哪条路线。

建议只显示，不发送站内消息。

# 21. 联系方式交换

## 21.1 前置条件

- 双方已完成名牌回赠；
- 相遇状态为 ACTIVE；
- 双方不存在拉黑；
- 目标名牌允许联系方式申请。

## 21.2 联系方式类型

- 微信二维码；
- 微信号；
- 手机号；
- 邮箱；
- 小红书；
- 微博；
- Instagram；
- GitHub；
- 个人网站；
- 自定义链接。

## 21.3 公开等级

### PUBLIC

用户主动设置为公开，可直接显示在名牌中，例如个人网站或公开作品集。

### PRIVATE

仅在联系方式申请通过后显示。

默认所有新建联系方式为 PRIVATE。

## 21.4 申请流程

1. A 点击申请交换联系方式；
2. A 选择愿意提供的联系方式；
3. B 收到申请；
4. B 选择愿意提供的联系方式；
5. B 同意或拒绝；
6. 同意后双方看到对方选定的信息。

不得自动共享全部联系方式。

## 21.5 状态机

```text
NOT_REQUESTED
  -> 发起 -> PENDING
PENDING
  -> 接受 -> ACCEPTED
  -> 拒绝 -> DECLINED
  -> 发起方撤回 -> CANCELLED
ACCEPTED
  -> 任意一方撤销小程序内展示 -> REVOKED
```

## 21.6 冷却和撤销

- 被拒后默认等待 7 天才能再次申请；
- 冷却时间由云端配置，不写死在多个客户端页面；
- 接受后任意一方可撤销小程序内展示；
- 撤销时提示：已经被对方复制或保存的信息无法从对方设备收回。

## 23.2 比例和尺寸

- 3:4：1080 × 1440；
- 9:16：1080 × 1920；

## 23.3 可选内容

# 24. 内容审核、举报与拉黑

## 24.1 审核对象

- 昵称；
- 一句话介绍；
- 标签；
- 自定义文本；
- 图片；
- 外部链接；
- 微信二维码图片；
- AI 输出写入后的最终内容。

开发 Agent 必须根据开发时最新微信官方能力核实具体审核 API，不得凭空编写接口名称。

## 24.2 审核规则

- 草稿可以保存；
- 公开发布前必须通过审核；
- 已发布名牌的新版本审核期间，旧版本继续公开；
- 审核失败需指出文字、图片或链接类别；
- 用户修改后可重新提交。

## 24.3 举报类型

- 色情或低俗；
- 骚扰；
- 仇恨或攻击；
- 冒充他人；
- 诈骗；
- 违法内容；
- 未经同意公开隐私；
- 其他。

举报保存被举报名牌快照，避免对方修改后丢失证据。

## 24.4 拉黑

拉黑后：

- 双方不能发起新认识请求；
- 双方不能申请联系方式；
- 待处理请求关闭；
- 当前用户相遇列表默认隐藏该用户；
- 不通知被拉黑者；
- 不自动删除安全审计数据。

# 25. 账号注销

## 25.1 注销要求

- 明确说明影响；
- 二次确认；
- 撤销所有公开名牌入口；
- 解绑未来 NFC 设备；
- 停止展示联系方式；
- 逻辑删除账号和用户内容；
- 按适用法律和平台规则处理安全审计、举报和交易无关的必要留存；
- 公开 `shareToken` 返回内容不可用页。

## 25.2 注销后的历史相遇

另一方相遇册可以保留当时的名牌快照，但显示：

> 该用户已注销。

不得继续打开其当前主页或联系方式。

# 26. 页面详细规格

## 26.1 P02 首页

### 无名牌

- 品牌区；
- 简短价值说明；
- 示例人格卡；
- 主按钮“创建我的第一张名牌”；
- 次级入口“看看名牌能怎么介绍一个人”。

建议文案：

> 不知道怎么开口介绍自己？先做一张漂亮的名牌，再把它递出去。

### 有草稿但无已发布名牌

> 你的名牌还没有完成。继续编辑，让它正式和别人见面。

操作：

- 继续编辑；
- 重新选择模板。

### 已有名牌

- 当前名牌预览；
- “递出这张名牌”主按钮；
- 分享、小程序码、生成图片；
- 切换当前名牌；
- 编辑；
- 创建新名牌；
- 待处理请求提示；
- 最近相遇。

## 26.2 P03 名牌类型选择

社交名牌：

> 介绍你的兴趣、性格和最近生活。适合聚会、活动和认识新朋友。

简历名牌：

# 27. 统一页面状态

## 27.1 加载

- 优先骨架屏；
- 不只显示无限旋转；
- 超时后提供重试；
- 返回页面可先展示缓存，再刷新服务端。

## 27.2 空状态

必须说明：

1. 为什么没有内容；
2. 可以做什么；
3. 一个明确主按钮。

不得只显示“暂无数据”。

## 27.3 失败状态

区分：

- 网络失败；
- 登录失效；
- 权限不足；
- 内容不存在；
- 正在审核；
- 已隐藏；
- 服务繁忙；
- 操作过频。

## 27.4 无权限

必须解释原因。例如：

> 先互相回赠名牌，才能申请交换联系方式。

不得只显示灰色按钮。

## 27.5 重复提交

关键操作：

- 按钮进入 loading；
- 禁止重复点击；
- 云函数使用幂等键或确定性业务键；
- 超时后先查询结果，再决定重试。

# 28. MVP 技术架构

## 28.1 客户端

- 微信原生小程序；
- TypeScript；
- WXML；
- WXSS；
- 原生组件；
- Canvas 2D 生成分享图片；
- 统一状态管理；
- 统一云函数调用封装；
- 统一错误处理和埋点。

不采用：

- Taro；
- uni-app；
- React 转换框架；
- 多端兼容框架。

## 28.2 服务端

采用微信云开发或 CloudBase：

- 云数据库；
- 云存储；
- 云函数；
- 微信用户身份识别；
- 环境变量；
- 日志；
- 必要的定时任务。

不在 MVP 单独搭建：

- NestJS 服务；
- PostgreSQL；
- Redis；
- 消息队列；
- Kubernetes；
- 微服务；
- 独立登录系统。

## 28.3 环境

至少区分：

- local；
- development；
- staging；
- production。

不同环境不得共用数据库、存储、微信配置、AI 密钥和审核服务配置。

## 28.4 数据原则

- 核心业务数据以服务端为准；
- 所有时间由服务端生成并存 UTC；
- 公共入口使用随机不可枚举 Token；
- 不在公开链接暴露 OpenID 或内部主键；
- 联系方式与公开名牌分开保存；
- 敏感字段仅通过云函数读取；
- 删除采用逻辑删除，公开入口立即失效；
- 关键业务保存名牌快照。

| 错误码 | 含义 | 用户提示 |
|---|---|---|
| AUTH_REQUIRED | 尚未登录 | 登录后才能继续这个操作 |
| ACCOUNT_RESTRICTED | 账号受限 | 当前账号暂时无法完成这个操作 |
| INVALID_INPUT | 输入非法 | 检查一下刚才填写的内容 |
| REQUIRED_FIELD_MISSING | 缺少必填 | 还有一些内容没有填写 |
| RESOURCE_NOT_FOUND | 内容不存在 | 这项内容已经不存在了 |
| FORBIDDEN | 无权限 | 你无法进行这个操作 |
| CARD_REQUIRED | 无可用名牌 | 先创建一张名牌，再介绍自己 |
| CARD_NOT_PUBLISHED | 名牌未发布 | 这张名牌还没有正式发布 |
| CARD_UNAVAILABLE | 名牌不可用 | 这张名牌暂时无法查看 |
| CONTENT_REJECTED | 内容审核未通过 | 部分内容需要修改后才能发布 |
| DUPLICATE_ACTION | 已完成 | 这个操作已经完成了 |
| GREETING_ALREADY_SENT | 已发请求 | 已经把名牌递出去了 |
| GREETING_EXPIRED | 请求过期 | 这次认识请求已经过期了 |
| GREETING_NOT_PENDING | 请求不可处理 | 这次认识请求已经无法处理 |
| RETURN_REQUIRED | 未完成回赠 | 先互相回赠名牌，再继续 |
| CONTACT_REQUEST_PENDING | 已有待处理申请 | 对方还没有处理上一次申请 |
| CONTACT_REQUEST_COOLDOWN | 冷却期 | 可以过几天再发起申请 |
| USER_BLOCKED | 存在拉黑 | 当前无法与对方互动 |
| RATE_LIMITED | 操作频繁 | 操作有点频繁，稍后再试 |
| UPLOAD_FAILED | 上传失败 | 图片没有上传成功，请重试 |
| AI_FAILED | AI 失败 | 刚才没有整理成功，可以重试 |
| IMAGE_EXPORT_FAILED | 图片生成失败 | 图片没有生成成功，请重试 |
| REVIEW_IN_PROGRESS | 正在审核 | 内容正在审核中 |
| NETWORK_ERROR | 网络问题 | 网络好像不太稳定 |
| SERVICE_UNAVAILABLE | 服务暂不可用 | 服务开了个小差，请稍后再试 |
| UNKNOWN_ERROR | 未知错误 | 暂时没有完成，请稍后再试 |

客户端不得直接展示内部异常文本。

# 34. 隐私与安全

## 34.1 最小化收集

- 不要求真实姓名；
- 不默认获取微信头像和昵称；
- 不采集精确位置；
- 不读取通讯录；
- 不追踪匿名访客身份；
- AI 只接收当前任务所需上下文。

## 34.2 敏感信息

上传前提示不要上传：

- 身份证；
- 护照；
- 银行卡；
- 家庭住址；
- 未经他人同意的隐私照片；
- 儿童敏感信息。

## 34.3 数据访问

- 公开名牌只返回 `publishedSnapshot` 中允许公开的字段；
- 私人联系方式不进入公开接口；
- 私人备注只返回给 owner；
- OpenID 不返回客户端公共页面；
- 数据库安全规则与云函数双重限制；
- 关键操作记录 requestId 和安全日志。

## 34.4 频率限制建议

具体值由配置决定，初始建议：

- 认识请求：每用户每小时有限次数；
- 同一目标短期不可重复；
- AI 每日有限调用；
- 举报和小程序码生成设置合理频率；
- 登录和云函数异常请求防刷。

开发 Agent 不得把数值散落写死在前端。

# 37. 测试与验收

## 37.1 创建流程

- 新用户创建社交名牌；
- 新用户创建简历名牌；
- 无真人头像可发布；
- 模块添加、隐藏、删除和排序正确；
- 更换模板不丢数据；
- 草稿退出后恢复；
- 图片失败可重试；
- 已发布名牌编辑时旧版本继续公开；
- 审核失败定位具体内容。

## 37.2 匿名浏览

- 未登录用户完整浏览；
- 不自动创建账号；
- 不通知名牌主人；
- 点击互动时才登录；
- 名牌不可用时显示正确状态。

## 37.3 收藏

- 收藏不通知对方；
- 收藏不创建请求；
- 重复收藏不重复写入；
- 取消收藏正确；
- 名牌删除后保留不可打开的快照提示。

## 37.4 双账号社交闭环

使用两个真实测试账号：

1. A 创建并发布名牌；
2. B 匿名浏览 A；
3. B 登录并创建名牌；
4. B 选择自己的名牌并向 A 发出认识请求；
5. A 收到通知；
6. A 查看 B 的名牌；
7. A 接受并回赠自己的名牌；
8. 双方进入相遇册；
9. 共同兴趣正确；
10. B 申请交换联系方式；
11. A 选择联系方式并同意；
12. 双方只看到对方选择提供的信息；
13. 任意一方撤销展示；
14. 状态同步正确。

## 37.5 权限与重复提交

- 用户不能编辑他人名牌；
- 用户不能读取他人私密联系方式；
- 用户不能读取他人私人备注；
- 重复点击认识请求不产生重复记录；
- 重复回赠不产生重复相遇；
- 重复接受联系方式不重复写入；
- 拉黑后不能继续互动；
- 已过期请求不能回赠；
- 注销后公开入口失效。

## 37.6 图片导出

- 三种比例均正确；
- 中英文、Emoji 和长文本不裁切；
- 各模板导出正常；
- 小程序码可用；
- 无授权时正确提示；
- iOS 和 Android 可保存。

## 37.7 真机要求

MVP 完成必须至少验证：

- 一台 iPhone；
- 一台 Android；
- 微信开发者工具；
- staging 云环境；
- 真实分享和小程序码链路。

仅在开发工具运行不算完成。

## 37.8 上线阻断问题

出现任一项不得上线：

- 匿名浏览被强制登录；
- 联系方式未经同意公开；
- 重复创建请求或相遇；
- 草稿频繁丢失；
- 未审核内容公开；
- 可读取或修改他人私密数据；
- 明显脚本注入或链接风险；
- iOS 或 Android 无法完成核心闭环；
- 图片严重错位；
- 注销后个人信息仍公开。

# 41. 未来路线

## 41.1 NFC 社交贴片

第一种实体形态优先采用可贴在现有吧唧、手机壳、工卡壳或其他物品背后的 NFC 社交贴片。

目标链路：

> 碰触 NFC → 打开动态入口 → 打开当前名牌或指定名牌。

要求：

- NFC 中只写入随机动态入口，不写个人资料；
- 用户可以解绑、重新绑定、停用和标记丢失；
- 原主人解绑后入口不再显示原资料；
- 保留二维码作为读取失败兜底；
- 具体唤起方式必须根据上线时的手机和微信平台能力验证。

## 41.2 电子吧唧

- 物理图案与数字名牌主题相关；
- 一枚吧唧可以代表用户的一个身份侧面；
- 不同吧唧可绑定不同固定名牌；
- 核心仍是现实相遇，不是硬件噱头。

## 41.3 电子工卡和卡套

- 适合行业活动和工作交流；
- 可以绑定简历名牌；
- 不发展为企业销售 CRM；
- 企业版是否存在需要后续独立论证。

## 41.4 自由创作

未来允许用户在模板基础上：

- 拖动模块；
- 调整层级；
- 创建自己的视觉组合；
- 发布用户共创模板。

在内容安全、性能和跨设备渲染稳定之前，不进入 MVP。
